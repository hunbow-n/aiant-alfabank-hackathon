# Модуль безопасности персональных данных

Прокси между системой-потребителем и LLM: находит персональные данные, маскирует их перед отправкой
в модель и восстанавливает в ответе. Ядро — правила, словари и контрольные суммы, без обращения к
внешним сервисам: `/process` отвечает за единицы миллисекунд.

**Демо-страница: https://pii.aiant.ru/** — вставьте свой текст и посмотрите весь путь: что ввели,
что ушло в модель, что она ответила, что получил потребитель.

---

## Как проверить за 5 минут

### 1. Маскирование и демаскирование

Откройте https://pii.aiant.ru/, вставьте текст с персональными данными и нажмите «Прогнать через
модуль». Панель 2 показывает **точный текст, покинувший защищённый контур** — по ней видно, что
данные не утекли в модель. Панель 4 — восстановленный ответ.

То же самое из консоли, по контракту проверки:

```bash
# Маскирование: первый запрос с новым payload_id
curl -s -X POST https://pii.aiant.ru/process -H 'Content-Type: application/json' \
  -d '{"payload":"Клиент Иванов Иван Иванович, паспорт 4509 123456","payload_id":"demo-1"}'
# {"result":"Клиент ****** **** ********, паспорт **** ******"}

# Демаскирование: тот же id, присылаем полученную маску
curl -s -X POST https://pii.aiant.ru/process -H 'Content-Type: application/json' \
  -d '{"payload":"Клиент ****** **** ********, паспорт **** ******","payload_id":"demo-1"}'
# {"result":"Клиент Иванов Иван Иванович, паспорт 4509 123456"}
```

Восстановление точное, позиции знаков сохраняются. Повторный запрос с тем же id и тем же исходником
возвращает ту же маску — эндпоинт идемпотентен к ретраям.

### 2. Точность и устойчивость к вариациям написания

На демо-странице есть готовые пресеты, нажмите по очереди:

| Пресет | Что проверяет |
|---|---|
| **Ловушки** | «Поэт Александр Пушкин» и «адрес отделения банка» **не маскируются** |
| **Нижний регистр** | `иванов иван иванович` находится так же, как с заглавных |
| **Дата прописью** | «двенадцатого марта тысяча девятьсот девяностого года» |
| **Склонения** | «Петрову Сергею Алексеевичу» |
| **Все типы ПД** | 17 обязательных категорий в одном тексте |
| **Без ПД** | обычный текст возвращается дословно, без единой маски |

### 3. Гибкая настройка и расширяемость

Настройка живёт в `config/systems.yaml` (пример — `config/systems.example.yaml`). На демо-странице
переключатели **«Система-потребитель»** и **«Вид маскирования»** меняют поведение на лету:

| Система | Типы ПД | Демаскирование | Маска |
|---|---|---|---|
| `chat-assistant` | все 17 | разрешено | токены `{{PERSON_1}}` |
| `bi-reports` | только 5 контактных | **запрещено** | звёздочки |

Что настраивается по каждой системе:

| Параметр | Значение |
|---|---|
| `enabled` | включает или отключает обращение системы в модуль |
| `detect_types` | какие типы искать |
| `mask_types` | какие из найденных маскировать |
| `demask` | разрешено ли восстановление для этой системы |
| `strategy` | `star`, `token` или `synthetic` |
| `combo_rules` | условное маскирование: `PIN` и `CVV` скрываются только вместе с номером карты |
| `ambiguity_mode` | `contextual` — строгий, `balanced` — допускает сильные форматные признаки |

**Новый тип ПД добавляется без правки ядра:** новый класс с интерфейсом `Detector` плюс строка в
конфиге. Существующие классы при этом не меняются.

### 4. Производительность

Время обработки каждой стадии показано прямо на демо-странице после прогона. Метрики —
`/actuator/prometheus` (наружу не публикуется, доступен с сервера).

Замеры на 4 ядрах:

| Профиль | Результат |
|---|---|
| Короткий запрос | 12–18 мс |
| 264 КБ (~60k токенов) | 289 мс |
| 528 КБ (~120k токенов) | 622 мс, восстановление точное |
| Пропускная способность | **5000 RPS**, p50 17 мс, p95 29 мс, p99 38 мс |
| Через nginx и HTTPS | 2000 RPS, 100% успешных |
| Ошибки и потери round-trip | 0 на 21 600 запросах |

Воспроизводится приложенным скриптом: `python3 tools/check_deployed.py https://pii.aiant.ru` —
53 проверки: контракт, утечки, ложные срабатывания, большие тексты, нагрузка.

### 5. Безопасность, логирование и метрики

Строка лога по каждому запросу — типы найденных ПД и их количество, **без единого значения**:

```
op=MASK payloadIdHash=20bc1a6e7846b847 len=48 types={PERSON=1, PASSPORT=1} latencyMs=3
```

- Значения ПД не попадают ни в логи, ни в метки метрик, ни в сообщения об ошибках.
- Сырой `payload_id` тоже не логируется, только его хэш: пользователь может положить в него ПД.
- Соответствие «маска → оригинал» шифруется **AES-256-GCM** эфемерным ключом, который создаётся при
  старте процесса и никуда не сохраняется.
- Потребительские API (`/api/v1/mask`, `/api/v1/unmask`) требуют `X-System-Id` и `X-Api-Key`;
  хранится только хэш ключа. Список систем конечный, неизвестная система получает 401.
- Метрики: latency по стадиям (p50/p95/p99), RPS, TPS (`cl100k_base`), счётчики по типам ПД, размер
  хранилища.
- Ошибки: невалидная схема — 400 с безопасным телом, перегрузка — 429 с `Retry-After`, отказ
  отдельного детектора не роняет запрос и фиксируется метрикой.

### 6. Расширенные сценарии

| Возможность | Где посмотреть |
|---|---|
| Токенизация и детокенизация | демо-страница, вид маскирования «Токены» |
| Замена синтетическими данными | демо-страница, вид «Синтетические данные» |
| Вид маскирования настраивается под систему | `strategy` в `systems.yaml` и переключатель на странице |
| RPS 2000 при latency ≤ 0,5 с | таблица замеров выше |
| Условное маскирование по комбинации типов | `combo_rules`: «ПИН без карты не маскируем» |
| Документы сверх паспорта РФ | СНИЛС с проверкой контрольной суммы |

## Как это устроено

```
Потребитель → POST /process → нормализация → детекторы → разрешение пересечений
            → маскирование → [ LLM ] → восстановление → Потребитель
```

Три слоя детекции:

1. **Строгие форматы с проверкой** — карта по алгоритму Луна, ИНН и СНИЛС по контрольным суммам,
   email, телефон, паспорт, ВУ, код подразделения. Минимум ложных срабатываний.
2. **Контекстные типы** — CVV, ПИН, гражданство, место рождения, орган выдачи, даты рождения и
   выдачи. Срабатывают только при подтверждающем контексте: три цифры сами по себе не CVV.
3. **Словари и морфология** — ФИО во всех падежах и любом регистре, адрес по компонентам. Публичные
   упоминания отсекаются по роли: «поэт» — не клиент, «отделение банка» — не адрес клиента.

Соответствие «маска → оригинал» живёт в памяти процесса 15 минут, затем ещё 5 минут остаётся
маркер, позволяющий честно ответить на поздний запрос. Хранилище не вытесняет активные пары под
давлением памяти: при исчерпании бюджета сервис отвечает 429, а не теряет данные.

## Запуск

```bash
./mvnw spring-boot:run          # локально, http://localhost:8080
docker compose up -d --build    # в контейнере
./mvnw test                     # 71 тест
```

| Переменная окружения | Назначение |
|---|---|
| `SERVER_PORT` | порт приложения, по умолчанию 8080 |
| `ALFAGEN_API_KEY` | ключ AlfaGen; без него демо работает со встроенным моком |
| `ALFAGEN_MODEL` | модель, по умолчанию `deepseek-ai/DeepSeek-V4-Flash-0731` |
| `CHAT_ASSISTANT_KEY_HASH` | SHA-256 ключа системы-потребителя `chat-assistant` |

## Инструкция по настройке

Скопируйте `config/systems.example.yaml` в `config/systems.yaml` и добавьте систему, указав её
идентификатор и ссылку на хэш API-ключа. Поля `enabled`, `detect_types` и `mask_types` управляют
доступом, обнаружением и маскированием данных. Поля `demask`, `strategy` и `combo_rules` задают
восстановление, способ замены и условия совместной обработки. Сохраните корректный файл и
перезапустите сервис: при ошибке конфигурации сервис не стартует и сообщает причину. Новые правила
маскирования применяются к новым сессиям, а отключение доступа или демаскирования — также к
существующим после перезапуска.

## Структура

```
api/            POST /process, потребительские mask/unmask, обработка ошибок
security/       аутентификация систем-потребителей
detect/rules/   детекторы по типам ПД — один класс на тип
classify/       контекст и роль упоминания: персональное или публичное
resolve/        разрешение пересечений кандидатов
mask/           стратегии: звёздочки, токены, синтетика
session/        хранилище соответствий, шифрование, TTL и маркеры
policy/         политики систем-потребителей и combo-правила
observability/  безопасные логи, метрики, счётчик токенов
admission/      бюджеты приёма и защита от перегрузки
demo/           демо-страница и её единственный эндпоинт
```

Подробности — в `docs/`: `ARCHITECTURE.md`, `STATE.md`, `DETECTORS.md`, `TESTING.md`,
`DECISIONS.md`, `BENCHMARK.md`.

## Ограничения и план развития

Честно о границах решения:

- **Состояние живёт в памяти одного процесса.** Перезапуск теряет незавершённые пары; горизонтальное
  масштабирование требует общего хранилища. Контракт хранилища уже выделен интерфейсом, реализация
  на Redis добавляется без изменения остального кода.
- **Окно восстановления — 15 минут.** Демаскирование позже возвращает честный 410, а не выдуманный
  результат.
- **Качество на эталонном датасете организаторов не измерялось** — он не публикуется. Наши цифры
  получены на собственном наборе и на приложенной батарее из 53 проверок.
- **Частичное покрытие адресов:** номер дома без метки после названия улицы («Тверская 7») и `кв`
  без точки пока не скрываются. Это неполная маска, а не пропуск сущности.
- **Литературные персонажи** распознаются как люди: «Евгения Онегина» будет замаскировано. Лечится
  словарём известных имён.
- **Демо-страница открыта без авторизации** намеренно, чтобы жюри могло проверить решение. В
  реальной эксплуатации она закрывается тем же механизмом, что и `/api/**`.

Дальше: общее хранилище для нескольких реплик, словарь публичных персон, расширение списка
документов, удостоверяющих личность, дообучение правил на реальном трафике.
