# Детекторы

Общий принцип: явная метка поля — сильное доказательство; форма, словарь и контрольная сумма —
признаки; соседний контекст — уточнение.

| № | Тип | Реализация |
|---|---|---|
| 1 | PERSON | Словари имён/отчеств/фамилий, суффиксы, контекст публичности |
| 2 | BIRTH_DATE | «дата рождения», «родился», «д.р.», «г.р.» + парсер дат |
| 3 | BIRTH_PLACE | «место рождения», «родился в» до границы поля |
| 4 | PASSPORT | 4+6 цифр, серия 2+2, раздельные диапазоны |
| 5 | CITIZENSHIP | «гражданство», «гражданин» + словарь стран |
| 6 | PASSPORT_ISSUER | Метка поля + МВД/УФМС/ОВД/ТП/ГУ до даты/кода |
| 7 | DEPARTMENT_CODE | 3-3 цифры с меткой поля |
| 8 | PASSPORT_ISSUE_DATE | «дата выдачи», «выдан» + паспортный контекст |
| 9 | DRIVER_LICENSE | Цифровые формы, старые с буквами, «ВУ», «права» |
| 10 | ADDRESS | Полный адрес и компоненты с метками полей |
| 11 | EMAIL | Практичный `local@domain`, границы пунктуации |
| 12 | PHONE | +7/8, скобки, дефисы, международный код |
| 13 | INN | 10/12 цифр, контрольные суммы |
| 14 | CARD | 13-19 цифр, Луна + контекст |
| 15 | CVV | 3 цифры при CVV/CVC/«код на обороте» |
| 16 | PIN | 4 цифры при «ПИН»/«PIN»/«пин-код» |
| 17 | CARDHOLDER | «имя держателя», «cardholder» |

## Даты

Общий парсер возвращает исходные диапазоны и набор допустимых календарных интерпретаций.
Поддержаны DMY, MDY, YMD, YDM; разделители `.`, `/`, `-`, пробел; год 4 и 2 цифры; русские
названия месяцев. Обычную дату встречи не маскировать только потому, что синтаксис валиден.

## Контрольные суммы

Совпадение формата плюс валидная сумма повышают уверенность; при отсутствии контекста неверная
сумма опускает её ниже порога; при явном персональном поле с типичной длиной ошибочный номер
скрывается как подозреваемый идентификатор.

## Персональность и неоднозначность

«Поэт Александр Пушкин» — публичная роль, «клиент Александр Пушкин» — персональное упоминание.
Режим `ambiguity_mode`: `contextual` для защищённых систем, `balanced` для benchmark.
