# Нагрузочные профили

## Профили

| Профиль | Что делает | Что подтверждает |
|---|---|---|
| Pair correctness | Новые ID, mask -> unmask, точная сверка | Корректность под реальным HTTP |
| Checker-like | До 200 соединений, ступени, 1:1 прямых и обратных | Поведение, близкое к прогону AlfaSonar |
| Throughput | Заданная скорость запросов | Достигнутые 1000 успешных HTTP RPS |
| Retry/race | Потеря ответа, повтор оригинала и маски | Идемпотентность, неизменность маски |
| Long soak | >= 25 минут | Плато памяти, работа sweep |
| Large | Тексты до 100k токенов | Время, heap, лимиты обратной маски |
| Mixed | Малые + 1% больших, затем 10% | Честная деградация |
| Fault | Исчерпание бюджета, ошибка детектора, рестарт | Безопасные отказы |

## Локальная приёмка производительности

- Не менее 1000 успешных корректных ответов в секунду на устойчивом участке 5 минут после прогрева.
- p99 <= 1 с; нет ответов дольше 10 с, неожиданных 5xx и потерь round-trip.
- Целевая доля 429 в основном профиле — 0%.
- Long soak: память выходит на плато, sweep успевает, вытеснения внутри TTL нет.

## Бюджеты

1. До десериализации: максимум байт тела, число одновременно читаемых тел, read timeout.
2. После схемы: in-flight bytes и разрешения на CPU-обработку. Чтение существующей пары имеет
   отдельный резерв.

Стартовые значения: разрешений на новые маски — по числу ядер; очередь ожидания короткая,
бюджет ожидания 50 мс, переполнение -> 429. Лимиты тела: 16 MiB декодированного payload и
128 MiB HTTP JSON.

## Фактические замеры

Оборудование: macOS, Apple Silicon, JDK 21, один процесс, состояние в памяти.

| Профиль | Результат |
|---|---|
| Короткий payload (128 символов) | 12 мс |
| 256 КБ (~60k токенов) | 334 мс |
| 512 КБ (~120k токенов) | 642 мс, round-trip точный |
| 50 параллельных клиентов, 2000 пар | 4922 HTTP RPS, p50 17 мс, p95 29 мс, p99 88 мс, ошибок 0 |

Требование ТЗ (1000 RPS при latency не более 1 с) выполняется с запасом. Соответствие
эталонному датасету организаторов не измерялось: датасет не публикуется.
